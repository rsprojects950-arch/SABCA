# Deep Linking & Password Reset Recovery

Password reset emails redirect mobile users back into the native app using the custom URI scheme **`sabcaapp://`** (`sabca-app/app.json` `"scheme": "sabcaapp"`).

## Native Scheme Configuration

<Tabs items={['iOS (SceneDelegate & Info.plist)', 'Android (AndroidManifest.xml)', 'Shared JS Parser']}>
  <Tab value="iOS (SceneDelegate & Info.plist)">
    Both `sabca-app/ios/SceneDelegate.swift` and `sabca-app/ios/SABCA/SceneDelegate.swift` implement `UIWindowSceneDelegate` URL forwarding so cold launches (`connectionOptions.urlContexts` / `connectionOptions.userActivities`) and warm launches (`scene(_:openURLContexts:)` / `scene(_:continue:)`) deliver links to `AppDelegate` (`ExpoLinking` & `RCTLinkingManager`). `Info.plist` registers `sabcaapp` under `CFBundleURLSchemes`.
  </Tab>
  <Tab value="Android (AndroidManifest.xml)">
    `sabca-app/android/app/src/main/AndroidManifest.xml` declares intent filters for `https`, `sabcaapp`, and `exp+sabca-app` schemes on `MainActivity.kt` (`singleTask` launchMode).
  </Tab>
  <Tab value="Shared JS Parser">
    `sabca-app/utils/authDeepLink.ts` exports `parseAuthDeepLink(url)` to decode Supabase implicit hash fragments (`#access_token` + `refresh_token`), PKCE query parameters (`?code`), OTP parameters (`?token_hash` + `type=recovery`), and explicit error payloads (`error`, `error_code`, `error_description`).
  </Tab>
</Tabs>

<Callout type="warn" title="Keep Both SceneDelegate.swift Copies Identical">
  A dedicated CI/unit test check in `tests/password_reset_deeplink.test.js` and `diff -u ios/SceneDelegate.swift ios/SABCA/SceneDelegate.swift` verifies that both Swift files remain identical. Never edit one copy without syncing the other, and inspect both after running `expo prebuild`.
</Callout>

## Recovery UI Safeguards (`app/(auth)/reset-password.tsx`)

- **URL Deduplication**: `AuthContext` tracks `processedAuthUrls` so repeated OS/Linking notifications for the same recovery URL do not re-trigger token exchange or race state updates.
- **Guard Flags**: While `isPasswordRecovery` or `isProcessingRecoveryLink` is `true`, `app/_layout.tsx` refuses to redirect an authenticated recovery session to `/(tabs)`.
- **Error & Timeout Fallback**: Expired OTPs or incomplete links surface actionable error copy after a **4-second** verification window, and Android hardware back navigation invokes `handleBackToLogin()` (clearing recovery flags, calling `signOut({ scope: 'local' })`, and navigating back to `/(auth)/login`).
